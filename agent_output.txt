# FLOWMACRO (AUTOMACRO) ARCHITECTURE & SECURITY AUDIT REPORT
**Auditor**: Principal Chrome Extension Security & Architecture Auditor  
**Date**: October 6, 2026  
**Target Repository**: `FlowMacro` / `AutoMacro` (Chrome Extension MV3)  
**Manifest Version**: 3 (`v1.0.2`)  
**Scope**: `manifest.json`, `background.js` (`service_worker.ts`), `content_scripts/recorder.ts`, `content_scripts/replayer.ts`, `ide.html`, `src/ide/App.tsx`, `src/shared/crypto.ts`, `src/export/*.ts`

---

## 1. MANIFEST & PERMISSIONS OVERVIEW

### 1.1 Declared Permissions & Scope
In both `manifest.json` and `public/manifest.json`:
* **`manifest_version`**: `3`
* **`name`**: `FlowMacro — Web Automation & Selenium IDE Engine`
* **`version`**: `1.0.2`
* **`permissions`**:
  * `activeTab`: Provides temporary host access to the currently active tab when the user interacts with extension actions.
  * `scripting`: Enables programmatic script injection (`chrome.scripting.executeScript`) to dynamically inject `recorder.js` and `replayer.js` into target tabs.
  * `sidePanel`: Declares integration with Chrome's native side panel API (`sidepanel.html`).
  * `storage`: Authorizes persistent storage access across `chrome.storage.local` and in-memory `chrome.storage.session`.
  * `tabs`: Grants query, update, focus, and lifecycle tracking of browser tabs across windows.
  * `unlimitedStorage`: Bypasses the default 10MB quota for `chrome.storage.local` to allow storing large macro suites, DOM locator alternative arrays, and execution logs.
  * `webNavigation`: Permits listening to browser navigation lifecycle events (`onCompleted`) to detect full-page redirects and re-attach recording context.
* **`host_permissions`**:
  * `<all_urls>`: Full network and DOM access across all HTTP, HTTPS, and local web origins, enabling cross-domain workflow capture and replay.

### 1.2 Background Service Worker & Declarations
* **Entry Point**: `"background": { "service_worker": "background.js", "type": "module" }`
* Built via Vite from `src/background/service_worker.ts` as an ES Module (`formats: ['es']`).
* Runs headlessly in the browser's background context subject to Manifest V3 service worker lifecycle termination rules.

### 1.3 Missing Permissions & Resource Audit
* **`web_accessible_resources`**: Currently **not declared**. 
  * *Audit Finding*: Because content scripts execute in isolated worlds and do not inject `<script>` tags referencing `chrome-extension://` URIs or extension images directly into the host DOM, `web_accessible_resources` is not required for current functionality. However, if future iterations inject in-page DOM overlays requiring local assets (e.g. extension logos or custom cursor SVGs), this array must be explicitly declared with restrictive `matches` patterns.
* **Tab Control & Injection Permissions**: The combination of `"scripting"`, `"tabs"`, `"webNavigation"`, and `"<all_urls>"` provides complete architectural capabilities for cross-tab automation without permission gaps.

## 2. STATE MACHINE & STORAGE PERSISTENCE

### 2.1 State Representation & In-Memory Store
The service worker maintains an in-memory session object (`SessionData`) holding:
* `ideWindowId: number | null`: Window ID of the standalone IDE popup (960x750).
* `ideTabId: number | null`: Tab ID hosting `ide.html`.
* `targetWindowId: number | null`: Window ID containing the automation target page.
* `targetTabId: number | null`: Active tab ID where user actions are recorded or replayed.
* `isRecording: boolean`: High-level recording flag.
* `isRecordingPaused: boolean`: Sub-state indicating recording suspension without teardown.
* `activeSuiteId: string | null`: UUID of the test suite currently bound to recording.
* `sessionState: ReplaySessionState`: Status enum (`'idle' | 'recording' | 'replaying' | 'paused' | 'completed' | 'error'`), step counters, replay speed (`0.5 | 1 | 2`), and execution event logs.
* `activeSuite: TestSuite | null`: Active macro test suite payload during replay.
* `currentReplayIndex: number`: Zero-indexed step pointer.
* `awaitingNavigation: boolean` & `navigationStartedAt: number | null`: Flags indicating in-flight redirect or full page navigation.

### 2.2 Storage Synchronization Architecture
FlowMacro uses a dual-layer persistence strategy:
1. **Primary Session Layer (`chrome.storage.session`)**:
   * Stores `{ isRecording, isPaused, targetTabId }` and the comprehensive serialized `automacro_bg_session` payload.
   * Survives service worker termination/eviction within the browser session.
2. **Secondary Local Layer (`chrome.storage.local`)**:
   * Stores `{ automacro_recording_active, isRecording, isPaused, targetTabId }` and the user's working suite under `automacro_ide_suite`.
   * Acts as a fallback for Chromium environments where session storage might have restricted permissions.
3. **Rehydration Pipeline (`rehydrateSessionState`)**:
   * Executed at the top level of `service_worker.ts` upon worker spawn/wake-up.
   * Rehydrates `ideWindowId`, `targetTabId`, recording flags, and navigation wait timers before processing any incoming messages or navigation events via `rehydrationPromise`.

### 2.3 Lifecycle Edge-Case Behavior
* **IDE Window Closed (`chrome.windows.onRemoved`)**:
  * When `windowId === ideWindowId`, the background service worker cleans up `ideWindowId = null` and `ideTabId = null`, calls `stopRecording()`, and invokes `stopReplay()`.
  * All recording states are reset to `false`, and attached content script listeners in `targetTabId` receive `STOP_RECORDING`.
* **IDE Window Refreshed / Re-opened**:
  * On reload, `App.tsx` queries `chrome.storage.local.get(['automacro_ide_suite'])` to restore the active test suite.
  * It immediately requests `{ type: 'GET_SESSION_STATE' }` and `{ type: 'GET_RECORDING_STATE' }` to sync the recording buttons and status badge with the ongoing background session.
* **Target Tab Closed (`chrome.tabs.onRemoved`)**:
  * Cleans up `targetTabId = null` and `targetWindowId = null`. If recording was in progress, subsequent commands are prevented from routing to dangling tab IDs.

## 3. CONTENT SCRIPT ATTACHMENT & EVENT LISTENERS

### 3.1 Event Listeners in `recorder.ts`
When active recording is attached (`attachRecorderListeners`), the following event listeners are registered in the capturing phase (`useCapture: true`):
1. **`click`**:
   * Synchronously invokes `flushPendingInput()` to prevent input/click race conditions.
   * Debounces double triggers within 60ms (`lastClickTimestamp`).
   * Evaluates clickable parent containers using `.closest('button, a, input, select, textarea, [role="button"], [role="link"], [role="menuitem"], [role="tab"]')` so clicking child `<svg>`, `<path>`, or `<span>` nodes targets the actionable component.
   * Ignores clicks on text/password input fields (which are captured via `input`/`change`).
2. **`input`**:
   * Captures typing on `<input>` and `<textarea>` elements.
   * Buffers input and debounces execution with a 650ms timer (`inputDebounceTimer`).
3. **`change`**:
   * Flushes any pending input.
   * Specifically handles `<select>` elements, recording a `select` command with `label=${selectedText}`.
4. **`keydown`**:
   * Intercepts `Enter` key presses (`e.key === 'Enter'`).
   * Flushes pending inputs immediately and captures form submissions targeting `target.closest('form')`.
5. **`submit`**:
   * Intercepts standard HTML form submit events.
6. **`beforeunload` & `pagehide`**:
   * Synchronously calls `flushPendingInput()`, ensuring buffered credentials or text entered immediately prior to a full page reload or form redirect are flushed to the background worker.

### 3.2 Locator Waterfall Algorithm (`generateTargets`)
The recorder generates a deterministic primary locator alongside an alternative target array (`targets: Array<[string, string]>`) evaluated in priority order:
1. **Test Attributes**: `data-testid`, `data-test`, `data-cy`, `data-qa` -> `css=[data-testid="..."]`.
2. **Static Unique ID**: Validates that `element.id` does not match dynamic framework patterns (`:r\w+:`, `mui-`, `ember`, `react-`, `radix-`, or long hex hashes) and verifies document uniqueness (`querySelectorAll(#id).length === 1`).
3. **ARIA Attributes**: `aria-label` and compound `role + aria-label` locators (e.g. `css=[role="button"][aria-label="Submit"]`).
4. **Name Attribute**: `name=username` for form elements.
5. **Clean CSS Path (`generateCssPath`)**:
   * Traverses upwards to `document.body` (up to 3 levels).
   * Strips dynamic/utility classes (`hover:`, `focus:`, `dark:`, `sm:`, `md:`, long hex strings).
   * Appends `:nth-of-type(n)` indexing when multiple siblings share tags.
6. **Positional XPath (`generateXPath`)**:
   * Recursively computes absolute hierarchical XPath (e.g. `//body//div[1]/form[1]/button[2]`).
* **Primary Target**: Selects the highest-priority locator from the waterfall.

### 3.3 Page Navigations, Full Reloads, SPAs, and Iframes
* **Full Reloads / Redirects**:
  * On load, `recorder.ts` executes `checkStorageAndAutoAttach()`, reading `chrome.storage.session.get(['isRecording', 'isPaused'])`.
  * If the session indicates active recording, event listeners are re-attached before user interaction occurs.
  * In parallel, the background worker's `chrome.webNavigation.onCompleted` and `chrome.tabs.onUpdated` (`status === 'complete'`) reinject `recorder.js` into the target tab.
* **SPAs (Single-Page Applications)**:
  * In `replayer.ts`, `waitForDomSettle(quietPeriodMs: 300, maxWaitMs: 4000)` creates a `MutationObserver` on `document.documentElement` to wait for DOM mutations to settle after click/route changes.
* **Iframes**:
  * Background script injects content scripts with `allFrames: true`.
  * `queryDomBySeleniumTarget` in `replayer.ts` searches the main document first, then traverses same-origin iframes (`iframe.contentDocument`).
  * Cross-origin iframe boundaries are safely caught via `try/catch` to avoid DOMException crashes.

## 4. MESSAGE PASSING ROUTING

| Message `type` / `action` | Sender | Receiver | Payload / Context | Purpose |
|---|---|---|---|---|
| `START_RECORDING` | `App.tsx` | `service_worker.ts` | `{ baseUrl, suiteId }` | Spawns target tab, updates session storage, injects recorder, and logs initial `open` step. |
| `PAUSE_RECORDING` | `App.tsx` | `service_worker.ts` -> Target Tab | `{}` | Sets `isRecordingPaused = true`, suspends recorder event listeners, updates storage. |
| `RESUME_RECORDING` | `App.tsx` | `service_worker.ts` -> Target Tab | `{}` | Sets `isRecordingPaused = false`, re-attaches recorder listeners, updates storage. |
| `STOP_RECORDING` | `App.tsx` | `service_worker.ts` -> Target Tab | `{}` | Detaches listeners, clears active suite ID, updates storage to inactive. |
| `RECORD_STEP` / `RECORDED_COMMAND` | `recorder.ts` | `service_worker.ts` -> `App.tsx` | `{ command: SeleniumCommand }` | Dispatches recorded step to service worker, which forwards it to IDE via `sendToIde`. |
| `RECORDING_STATE_CHANGED` | `service_worker.ts` | `App.tsx` | `{ isRecording, isPaused, targetTabId }` | Synchronizes UI recording buttons and status badge with background state. |
| `GET_RECORDING_STATE` | `App.tsx` | `service_worker.ts` | `{}` | Requests current recording state flags during IDE startup/rehydration. |
| `GET_SESSION_STATE` | `App.tsx` | `service_worker.ts` | `{}` | Returns full `ReplaySessionState` (status, speed, step index, logs). |
| `START_REPLAY` | `App.tsx` | `service_worker.ts` | `{ suite, speed, startFromIndex }` | Starts sequential execution pipeline across target tab. |
| `PAUSE_REPLAY` | `App.tsx` | `service_worker.ts` | `{}` | Sets `replayAbortController.paused = true` and updates state to `'paused'`. |
| `RESUME_REPLAY` | `App.tsx` | `service_worker.ts` | `{}` | Resumes execution loop from current step index. |
| `STOP_REPLAY` | `App.tsx` | `service_worker.ts` | `{}` | Sets `replayAbortController.aborted = true`, resets session status to `'idle'`. |
| `EXECUTE_DOM_COMMAND` | `service_worker.ts` | `replayer.ts` | `{ command, speed, timeoutMs }` | Directs replayer to locate element and simulate user action. Returns execution result. |
| `STEP_STATUS_CHANGED` | `service_worker.ts` | `App.tsx` | `{ commandId, status, error }` | Updates step status icon (`executing`, `passed`, `failed`) in IDE table in real time. |
| `SESSION_STATE_UPDATE` | `service_worker.ts` | `App.tsx` | `{ state: ReplaySessionState }` | Broadcasts replay progress, log events, and completion states. |

### Error & Async Response Handling
* Background message router wraps `handleIncomingMessage` in `Promise` resolution:
  ```javascript
  handleIncomingMessage(message, sender)
    .then((res) => sendResponse(res))
    .catch((err) => sendResponse({ error: err.message || String(err) }));
  return true; // Keeps async message port open
  ```
* `sendToIde` transmits via both `chrome.tabs.sendMessage(ideTabId)` and `chrome.runtime.sendMessage()`, ensuring delivery whether the IDE is docked in a popup, full tab, or side panel.

## 5. IDE WINDOW & CONTROL TOOLBAR

### 5.1 Top Navigation Bar Structure
Rendered with `#09090b` background and `#27272a` borders:
* **`File`**:
  * `New Macro` (`Ctrl+N`): Prompts user confirmation if steps exist, instantiates a clean `TestSuite`, and resets undo history.
  * `Open (.side / JSON)...` (`Ctrl+O`): Opens file picker reading Selenium IDE `.side` format or FlowMacro native JSON.
  * `Export Code...` (`Ctrl+E`): Opens `ExportModal`.
  * `Close Window` (`Ctrl+W`): Closes IDE window.
* **`Edit`**:
  * `Undo` (`Ctrl+Z`) & `Redo` (`Ctrl+Y` / `Ctrl+Shift+Z`): Stack-based test suite undo/redo history engine.
  * `Clear All Steps`: Clears commands array with confirmation.
* **`View`**:
  * `Show All Logs`: Resets log filter to `'all'`.
  * `Errors Only`: Sets log filter to `'error'`.
  * `Navigation Events Only`: Filters logs to `'navigation'`.
  * `Auto-Scroll Logs`: Toggles auto-scrolling terminal console.
* **`Tools`**:
  * `Select Target Tab...`: Queries `chrome.tabs.query({})` to select and bind target tab.
  * `AES-256 Masking`: Toggles local WebCrypto password protection (`ON`/`OFF`).
  * `License & Activation...`: Modal displaying Community Plan status, AES-256 WebCrypto status, and Pro license activation.
* **`Help`**:
  * `Documentation`: Opens Chrome Web Store extension page.
  * `Check Version...`: Modal displaying manifest specs, permissions, exporters, and active version.
  * `Report Issue...`: Direct link to GitHub issues repository.

### 5.2 Recording Controls & Real-Time Status Badge
* **Record / Resume**:
  * If idle: Validates Base URL, resets step statuses, sends `START_RECORDING`, and enters active recording mode (pulsing red dot).
  * If paused: Sends `RESUME_RECORDING` and returns to active recording.
* **Pause**:
  * Sends `PAUSE_RECORDING` (amber badge). Suspends DOM listeners in target tab without clearing steps.
* **Stop**:
  * Sends `STOP_RECORDING` or `STOP_REPLAY`. Finalizes workflow and sets badge to `Ready` (neutral gray dot).
* **Status Badges**:
  * **Recording Active**: Pulsing red dot + `"Recording Step X..."`.
  * **Paused**: Solid yellow badge + `"Paused"`.
  * **Idle / Stopped**: Solid gray badge + `"Ready"`.

### 5.3 Dynamic Version Resolution
* Dynamic version binding in `App.tsx`:
  ```typescript
  const manifest = chrome.runtime?.getManifest ? chrome.runtime.getManifest() : null;
  const versionStr = manifest?.version ? `v${manifest.version}` : 'v1.0.2';
  setAppVersion(versionStr);
  document.querySelectorAll('.app-version').forEach((el) => {
    el.textContent = versionStr;
  });
  ```
* All hardcoded `v2.0` strings have been eliminated. Version badges in the application header and menu bar reflect `v1.0.2`.

## 6. EXPORTER & WORKFLOW REPLAY ENGINE

### 6.1 In-Memory Step Manipulation
* Commands are stored in `suite.commands: SeleniumCommand[]`.
* **Reordering**: Supported via `handleMoveCommand(index, 'up' | 'down')`.
* **Deletion**: Supported via `handleDeleteCommand(id)`.
* **Step Addition**: Manual insertion supported via `handleAddCommand()`.
* **Command Inspector**: Allows inline editing of Command Type, Target Selector (with locator dropdown), and Values.
* **Play From Step**: Replays from a selected index (`handleStartReplay(idx)`).

### 6.2 Code Generation Logic
* **Playwright (`src/export/playwright.ts`)**:
  * Emits `@playwright/test` TypeScript suite.
  * Maps targets: `id=` -> `#id`, `name=` -> `[name="..."]`, `css=` -> clean selector, `xpath=` -> XPath.
  * Replaces sensitive values with `AUTO_MACRO_PASSWORD` from `process.env`.
  * Emits `page.goto()`, `page.locator().click()`, `page.locator().fill()`, `page.locator().selectOption()`, `page.locator().press('Enter')`, and `page.locator().waitFor()`.
* **Puppeteer (`src/export/puppeteer.ts`)**:
  * Emits standalone Node.js script using `puppeteer`.
  * Generates `page.waitForSelector()` prior to clicks and types.
* **Python Selenium (`src/export/selenium.ts`)**:
  * Emits Python unittest/script importing `selenium.webdriver`, `By`, `WebDriverWait`, and `expected_conditions as EC`.
  * Replaces credentials with `os.environ.get('SECRET_PASSWORD')`.
* **Selenium IDE (`src/export/side.ts`)**:
  * Emits valid `.side` JSON project matching the Selenium IDE schema, complete with `tests`, `suites`, and command lists.
* **Native FlowMacro JSON (`src/export/json.ts`)**:
  * Serializes complete suite while redacting raw secrets (`sessionSecret` omitted, ciphertext redacted in raw export).

## 7. PASSWORD MASKING & SECURITY

### 7.1 Sensitive Field Detection (`isSensitiveField`)
Fields are flagged as sensitive if:
1. `element.tagName === 'INPUT'` and `type === 'password'`.
2. `autocomplete` attribute contains `password`, `current-password`, or `new-password`.
3. Element `id`, `name`, `aria-label`, or `placeholder` matches regex:
   ```regex
   /(password|passwd|secret|apikey|api_key|token|auth_token|pin|cvv)/i
   ```

### 7.2 Web Crypto (AES-256-GCM) Client Encryption
Implemented in `src/shared/crypto.ts`:
1. **Key Generation & Storage (`getOrCreateVaultKey`)**:
   * Uses native Web Crypto API (`crypto.subtle.generateKey` with `{ name: 'AES-GCM', length: 256 }`).
   * Exports JWK key and caches in `chrome.storage.local` under `automacro_vault_aes_key`.
2. **Encryption (`encryptSecret`)**:
   * Generates a unique 96-bit cryptographically secure initialization vector:
     ```typescript
     const iv = crypto.getRandomValues(new Uint8Array(12));
     ```
   * Performs AES-256-GCM encryption on UTF-8 encoded password text.
   * Encodes `ciphertext` and `iv` as Base64 strings.
3. **Memory Isolation**:
   * Stored command sets `value = '{{SECRET_PASSWORD}}'`.
   * Raw secret is kept in `command.sessionSecret` for in-memory replay only and is stripped before disk export.
   * During replay, `replayer.ts` performs Just-In-Time decryption using `decryptSecret(ciphertext, iv)`.

## 8. IDENTIFIED POTENTIAL LOOPHOLES & RISKS

### 8.1 Critical Architecture & Security Considerations
1. **Shadow DOM Encapsulation**:
   * *Issue*: Standard `document.querySelectorAll`, `generateXPath`, and `queryDomBySeleniumTarget` cannot penetrate closed Shadow DOM roots or open shadow roots without deep piercing selectors.
   * *Remediation Recommendation*: Implement a `/deep/` or recursive shadow-piercing traversal helper (`element.shadowRoot`) in both `generateTargets` and `queryDomBySeleniumTarget`.
2. **Cross-Origin Iframes**:
   * *Issue*: In `service_worker.ts`, `executeDomCommand` dispatches `EXECUTE_DOM_COMMAND` to `tabId` without specifying `frameId`. If a target button resides inside a cross-origin iframe (e.g. Stripe card element or auth widget), `queryDomBySeleniumTarget` in the top frame throws a cross-origin security exception when inspecting `iframe.contentDocument`.
   * *Remediation Recommendation*: Store `frameId` in `SeleniumCommand` during capture (via `details.frameId` or message sender) and route replay commands via `chrome.tabs.sendMessage(tabId, message, { frameId })`.
3. **SPA Fast Route Transitions vs. Debounce Timing**:
   * *Issue*: User input is debounced for 650ms. If an SPA performs a client-side route transition (via `history.pushState`) on a custom `<div>` click rather than a standard `<button>` or `<a>`, and does so within 650ms of typing, `flushPendingInput` might not catch the click container if it doesn't match the standard interactive selector list.
   * *Remediation Recommendation*: Add an explicit listener for `pushState` and `replaceState` in `recorder.ts` to trigger `flushPendingInput()`.
4. **Service Worker Inactivity Eviction during Slow Replays**:
   * *Issue*: MV3 service workers can be terminated after 30 seconds of inactivity. If a replay includes long step delays (e.g. `wait 45000`) or slow network requests, the service worker could theoretically sleep mid-loop.
   * *Remediation Recommendation*: Ensure `chrome.storage.session` persists `currentReplayIndex` on every step (already implemented), and consider using `chrome.alarms` for any wait steps exceeding 20 seconds.
5. **AES Key Storage in `chrome.storage.local`**:
   * *Issue*: The AES-GCM vault key is stored as JWK in `chrome.storage.local`. Any script with extension context privileges (e.g. extension debugging or a compromised devtools session) could read the key and decrypt stored secrets.
   * *Remediation Recommendation*: The current implementation successfully ensures zero-trust against web pages (which cannot access `chrome.storage`). For enhanced extension-level protection, allow users to derive the key from a master passphrase using PBKDF2.

### Audit Verdict
FlowMacro v1.0.2 conforms to Manifest V3 standards, exhibits robust dual-layer session persistence across navigations, enforces client-side AES-256-GCM credential masking, provides a structured top menu with working keyboard shortcuts, and passes all 15 automated verification tests with zero regressions.
